# Separate compatibility defaults from semantically valid specialization

Chrono will keep family semantics explicit while maximizing interoperability: shared compatibility metadata such as `MinDate` and `MaxDate` belongs on `IReadOnlyTimeSeries<T>` and refers to explicit-point bounds, while bounded stepwise logical coverage remains a separate concept. Default arithmetic and aggregation/resampling APIs will preserve exact concrete types when both inputs share that exact type, but mixed concrete types will fall back to the shared contract backed by `SortedArrayTimeSeries<T>`; cross-family operations must preserve sparse semantics rather than implicitly densifying, periods must already match unless resampling is requested explicitly, and specialized `Try...As...` APIs may return family-specific results only when that target family is semantically valid for the operation.
